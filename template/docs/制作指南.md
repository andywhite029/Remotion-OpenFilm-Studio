# 制作指南

[返回首页](../README.md) · [开发规范](开发规范.md) · [素材与渲染](素材与渲染.md)

从模板派生一条片子，再按「分镜 → 时间轴 → 视觉 → 画面 → 验收」推进。首次安装和预览命令见[首页](../README.md)。

## 派生新项目

一个仓库维护一条主线片及其内容变体。不同节拍结构、画幅或品牌使用独立目录；同片深色版可使用 git 分支，始终保持单一 `SEG` 和 `C`。

复制模板时排除依赖、产物和原仓库历史。Windows 示例（替换源和目标路径，使用新的目标目录）：

```powershell
robocopy "D:\projects\video-template" "D:\projects\product-film" /E /XD node_modules out .git .remotion
cd "D:\projects\product-film"
npm install
npm run doctor
git init
```

`robocopy` 的退出码 0–7 通常表示成功或有差异，≥8 表示复制失败。若要保留模板提交历史以便后续合并改进，可用 git 克隆，再修改远程地址。

派生后依次调整：

| 内容 | 修改位置 | 注意 |
| --- | --- | --- |
| 项目身份 | [package.json](../package.json) 的 `name` / `description` | 保留 ESM 与脚本配置 |
| 分镜和时长 | [timeline.ts](../src/timeline.ts) | 改 `SEG` 与 `VIDEO`，不另建时间轴 |
| 品牌与视觉 | [theme.ts](../src/theme.ts) | 改完检查对比度 |
| 示例画面 | [Main.tsx](../src/sequences/Main.tsx) | 逐拍替换内容 |
| 素材与交接 | [public](../public/) 与 [HANDOFF.md](../HANDOFF.md) | 记录未进 git 的素材获取方式 |

## 制作顺序

### 1. 定论点与分镜

先写清「给谁看、希望观众记住什么、交付到哪里」，再用表格排每一拍。15 秒短片可先从 3–6 拍开始，确保文案有足够阅读时间。

| beat | 时长 | 观众应记住什么 | 画面 |
| --- | --- | --- | --- |
| title | 2 秒 | 产品和主题 | 标题、副标 |
| statement | 3 秒 | 核心问题 | 一句话与证据 |
| demo | 7 秒 | 解决方式 | 产品演示或图表 |
| end | 3 秒 | 结论与下一步 | 结束卡 |

此表用于策划；实际 key 和时长统一落入时间轴，不在组件内复制帧号。

### 2. 排时间轴

在 [timeline.ts](../src/timeline.ts) 修改 `SEG`：`from` 含、`to` 不含，片段按顺序排列且不重叠；有意留白也要在审片时确认。`TIMELINE_END` 自动推导，`VIDEO.DURATION` 必须覆盖它。

```bash
node tools/checkTimeline.ts
```

例如把某拍提前，需要同时调整前一拍终点。画幅改变还需要重排版式和安全区，不能只改宽高。

### 3. 定视觉与写画面

先在 [theme.ts](../src/theme.ts) 确定配色和视觉令牌，再写 [sequences](../src/sequences/) 中的内容；共享组件与视觉约束见[开发规范](开发规范.md)。

```bash
node tools/checkContrast.ts
npm run dev
```

组件读取 `frame`、`SEG` 和主题令牌。素材接入方法见[素材与渲染](素材与渲染.md)，新增合成的注册规则见[开发规范](开发规范.md)。

### 4. 校对与出片

先检查每拍中段和切点附近的关键帧，再用草稿通看节奏：文字是否读得完、转场是否闪烁、素材是否覆盖整段。静帧通常每帧都重新打包，先选少量关键帧。

```bash
npm run check
npm run stills -- Main --frames 30,90,210,330,420
npm run render:draft
npm run render:hq
```

以上帧号对应模板示例，调整时间轴后应重新选择。交付要求 limited-range `yuv420p` 时使用 `render:master`，并核对最终媒体信息，详见[素材与渲染](素材与渲染.md)。

验收时确认：

- `npm run check` 全绿，`npm run doctor` 无未解决的 `FAIL`。
- 所有 beat 的文字、数字与素材来源正确，关键帧无溢出或意外空白。
- 整片转场、停留、音画同步与结尾符合预期；包含 3D 时确认画面非空。
- 最终文件的尺寸、fps、时长、像素格式与交付要求一致。
- [HANDOFF.md](../HANDOFF.md) 已记录最终命令、素材获取方式、授权和待办。

## 改动后验证什么

交付前始终运行 `npm run check`；开发过程中可先跑针对性检查。

| 改动 | 追加验证 |
| --- | --- |
| 文案、版式 | 相关静帧和局部渲染 |
| 时间轴 | `node tools/checkTimeline.ts`，整片节奏 |
| 颜色与主题 | `node tools/checkContrast.ts`，关键帧 |
| 素材 | `node tools/checkAssets.ts`，素材所在片段 |
| 合成注册 | `npm run compositions` |
| 共享组件、全局渲染配置 | Main 和 ThreeDemo 草稿渲染 |
| 仅文档 | 链接与命令核对，无需重新渲染 |

## 维护与交接

版本以 [package.json](../package.json) 和 [package-lock.json](../package-lock.json) 为准，不在文档维护第二份依赖版本表。`remotion`、`@remotion/cli`、`@remotion/three` 必须完全同版本。

升级前保存当前可回滚的状态，再执行：

```bash
npm run upgrade
npm run doctor
npm run check
npm run compositions
npm run stills -- Main --frames 30
node scripts/render.mjs Main --preset draft
node scripts/render.mjs ThreeDemo --preset draft
node --test scripts/local-public-assets.test.mjs
```

升级后还需复核[本地素材复用适配](../scripts/local-public-assets.mjs)：它依赖 Remotion 内部接口，版本不匹配会警告并回退下载流程。失败时在版本控制中恢复升级前的依赖清单与 lockfile，再重新安装。

[lib](../src/lib/)、[components](../src/components/) 和 [three](../src/three/) 是共享引擎。项目专属版式留在内容层；经过多项目验证的通用改进再回收到模板。

提交前检查 `git status`。[.gitignore](../.gitignore) 已排除依赖、产物和部分大素材；新增素材仍需检查是否被正确忽略，避免把序列帧或大型模型提交进仓库。交接只在 [HANDOFF.md](../HANDOFF.md) 记录当前项目事实，不复制整份使用手册。
