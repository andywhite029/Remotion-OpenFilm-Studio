## 素材接入

默认将视频、图片、音频和字体放入 [public](../public/)，使用 `staticFile()`；小图标也可放入 [src/assets](../src/assets/) 并用 `import` 打包，资源类型声明见 [global.d.ts](../src/global.d.ts)。

```tsx
import {Audio, Img, OffthreadVideo, staticFile} from 'remotion';

<Img src={staticFile('media/hero.png')} />
<OffthreadVideo src={staticFile('media/clip.mp4')} />
<Audio src={staticFile('audio/theme.mp3')} volume={0.8} />
```

`staticFile()` 参数不要带 `public/` 前缀，不要手写 `/media/…` 或传本机绝对路径。远程 URL 直接传给组件，但渲染机需要能够访问它。

| 素材 | 接入要点 |
| --- | --- |
| 图片 | 用 Remotion `Img` 等待加载；按显示尺寸准备，透明图可用 PNG / WebP |
| 视频 | 优先 `OffthreadVideo`；先核对 fps、时长、音轨；需要统一采样或降低解码成本时预转码为合成 fps 的 H.264 / yuv420p |
| 音频 | 用 `Audio`；音量动画由帧进度驱动；裁剪、淡入淡出的时间统一从 `SEG` 推导 |
| 字体 | 品牌字体放入 [public/fonts](../public/fonts/)；等待 `FontFace.load()` 完成后再 `continueRender()`，失败用 `cancelRender()` 明确报错 |
| 3D | GLB 与贴图可放入 public 下自建 models 目录；等待异步加载，成功时推进 r3f 帧循环后释放渲染阻塞 |

系统字体会随机器变化。需要逐帧一致的交付，应固定字体文件与字体加载流程。异步资源的每条成功、失败路径都必须结束阻塞，不能静默渲出缺字或空模型。

项目默认 3D 为程序化几何，入口见 [Stage.tsx](../src/three/Stage.tsx) 和 [Spinner.tsx](../src/three/Spinner.tsx)。接入 GLB 时，项目现有约定是在 loader 的 `onLoad` 中调用 `advance(performance.now())`，再 `continueRender()`；这一步用于提交加载后的场景，动画仍由 `frame` 决定。

### 序列帧与网页截图

需要逐帧选图、遮罩或排查视频解码时可使用序列帧。它会显著增加体积，不适合无条件替代长视频。

```bash
npm run media -- from-video public/media/source.mp4 --out public/media/frames --fps 30
```

脚本输出从 `0001.png` 开始，组件应将素材内局部帧映射为 `localFrame + 1`，并检查范围，避免越界 404。慢放后的预计帧数约为 `原帧数 / speed`。

产品网页需要可重复的演示画面时，可用 Playwright 固定 viewport、等待字体、关闭非确定性动画，再按帧号计算滚动与交互位置并截图。模板未内置网页录屏或 USD → GLB 转换脚本；后者可用 Blender 导入 USD 后导出 glTF 2.0，并检查材质与贴图。

### 媒体工具

[media.mjs](../scripts/media.mjs) 需要系统安装 ffmpeg；可选 ffprobe 用于媒体信息探测。二进制路径可通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定。

| 命令 | 用途 |
| --- | --- |
| `npm run media -- probe out/Main.mp4` | 查看容器、时长、码率与流 |
| `npm run media -- from-video public/media/source.mp4 --out public/media/frames --fps 30` | 导出序列帧 |
| `npm run media -- retime public/media/source.mp4 out/slow.mp4 --speed 0.5` | 重定时；此工具丢弃音频 |
| `npm run media -- to-gif out/Main.mp4 out/preview.gif --fps 12 --width 480` | 导出 GIF |
| `npm run media -- mux-audio out/Main.mp4 public/audio/theme.mp3 out/scored.mp4` | 合音轨，视频不重编码 |
| `npm run media -- contact-sheet public/media/frames out/contact.jpg` | 序列帧联系表 |

所有子命令均支持 `--help`，例如 `node scripts/media.mjs retime --help`。素材来源、许可、能否进 git 及获取方式统一记录在 [HANDOFF.md](../HANDOFF.md)。

## 渲染参数

[render.mjs](../scripts/render.mjs) 提供三档预设；[remotion.config.ts](../remotion.config.ts) 统一设置入口、public 目录、H.264、ANGLE、覆盖输出和 60 秒异步加载超时。

| CPU 预设 | 尺寸 | 编码参数 | 中间帧 | 用途 |
| --- | --- | --- | --- | --- |
| `draft` | 合成尺寸 ×0.5 | CRF 28 | JPEG | 节奏与草稿审片 |
| `hq`（默认） | 合成原尺寸 | CRF 18 | JPEG | 常规交付 |
| `master` | 合成原尺寸 | CRF 14、x264 slow | PNG | 较高质量、要求 limited-range yuv420p 的交付 |

```bash
node scripts/render.mjs Main --preset draft --frames 0-89
node scripts/render.mjs Main --preset hq --concurrency 4 --out out/review.mp4
node scripts/render.mjs ThreeDemo --preset draft --out out/three.mp4
node scripts/render.mjs --help
```

| 参数 | 含义 |
| --- | --- |
| 合成 id | 第一个位置参数，默认 `Main`；`npm run compositions` 查看注册项 |
| `--frames A-B` | 含两端；`0-89` 为 90 帧，在 30fps 下是 3 秒 |
| `--out` | 输出文件或目录；默认 `out/<id>.mp4`，已有目录或带尾斜杠时补文件名 |
| `--concurrency N` | 并发页面数；默认交给 Remotion，内存不足时降低 |
| `--encoder cpu\|gpu` | 默认 CPU；GPU 规则见下节 |

退出码：`0` 成功、`1` 渲染失败、`2` 参数错误。渲染后报告优先用 ffprobe，缺失时尝试 `ffmpeg -i`；两者都不可用时仍能报告输出文件大小。

当前版本实测：JPEG 中间帧会使输出为 full-range `yuvj420p`，即使全局配置声明 `yuv420p`。需要 limited-range `yuv420p` 时使用 PNG 中间帧的 `master`，并检查成片；`master` 仍是有损 H.264，不是无损母版。

```bash
npm run media -- probe out/Main.mp4
ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt,color_range -of default=nw=1 out/Main.mp4
```

### 静帧

```bash
npm run stills -- Main --frames 0,150,300 --scale 0.5
```

[stills.mjs](../scripts/stills.mjs) 默认按 [timeline.ts](../src/timeline.ts) 的 `VIDEO.DURATION` 均分 8 帧，输出到 `out/stills/<Id>-frame-<帧号4位>.png`。每张图都会独立调用 CLI 并重新打包，优先选每拍中段与切点附近的少量帧。自定义短合成应显式指定帧号，避免按主时间轴取帧越界。

## GPU 编码

```bash
npm run render:hq -- --encoder gpu
node scripts/render.mjs Main --preset draft --encoder gpu --frames 0-89 --out out/gpu-smoke.mp4
```

GPU 模式要求硬件编码可用，失败就报错。它使用目标码率，避免 CRF / x264 preset 与硬件编码冲突：

| 预设 | 视频码率 | 中间帧 |
| --- | --- | --- |
| draft | 4 Mbps | JPEG，半分辨率 |
| hq | 16 Mbps | JPEG |
| master | 32 Mbps | PNG |

这些码率不保证与 CPU CRF 等价的质量。Windows / Linux 使用受支持的 NVENC，macOS 由 Remotion 选择 VideoToolbox。Studio 导出时需单独设置 hardware acceleration 为 `required`，并使用目标码率质量控制。

硬件编码只加速视频压缩；React 布局、截图、素材解码仍可能占主要时间。ANGLE 是 WebGL 配置，与视频编码是不同环节。Windows 上可观察 GPU 的 Video Encode 图表确认编码负载。

## 本地素材复用

[render.mjs](../scripts/render.mjs) 会预加载 [local-public-assets.mjs](../scripts/local-public-assets.mjs)，将本次渲染服务的 `/public/…` URL 映射为本地 bundle 文件，避免 `OffthreadVideo` 再下载一份到临时目录；组件继续使用 `staticFile()`，音频分析保持原流程。

- 仅消除 renderer 下载阶段的副本；打包 public 到 bundle 的副本仍保留。
- 远程 URL、data URL、非 public 或无法映射的文件走原有下载或报错流程。
- 直接运行 `npx remotion …`、静帧脚本、Studio 导出不自动加载此适配。
- 内部接口适配限定 Remotion 4.0.541；版本不匹配会提示并回退，升级后需复核。

回归验证（需要 ffmpeg）：

```bash
node --test scripts/local-public-assets.test.mjs
```

## 排错

先执行 `npm run doctor`，再按症状定位。不要用放宽校验器来掩盖问题。

| 症状 | 检查与处理 |
| --- | --- |
| Node 不能直接运行 TS | 推荐 Node 24 LTS；旧版 Node 22 需类型剥离开关或升级，用 doctor 确认 |
| 素材 404 | 文件是否存在、`staticFile()` 是否去掉 public 前缀；动态拼接路径还需实际渲染验证 |
| 字体回退或缺字 | 检查字体覆盖范围，等待加载，固定交付字体文件 |
| `delayRender()` 超时 | 检查资源 URL、网络、每条成功/失败分支是否释放阻塞；GLB 是否提交加载后的场景 |
| 3D 黑屏 | 渲染 ThreeDemo 对照；若也黑，检查 ANGLE、浏览器与 GPU 驱动，再检查相机、灯光、模型 |
| 内存不足或渲染进程被杀 | 降低 `--concurrency`，用 draft 或局部帧段定位；检查磁盘空间 |
| 首次下载 Chrome | 等待下载或预置缓存；路径由 Remotion 管理，勿依赖某台机器的绝对路径 |
| ffprobe 不可用 | 不阻止视频渲染；安装系统 ffprobe 或设置 `FFPROBE_PATH`，Windows 动态构建需保留同目录 DLL |
| npm 安装脚本受限 | 先确认打包是否正常；本机曾出现 esbuild 告警但 optionalDependencies 二进制可用，不代表所有安装失败都可忽略 |

需要指定本地浏览器时，设置 `REMOTION_BROWSER` 为可执行文件路径（由全局配置读取），再重试。路径含中文或空格时，自动化用 Node `path` API 与参数数组；脚本修改应明确使用 UTF-8，不用 `.sh` 包装 npm 命令。

`ffmpeg -i <文件>` 的媒体信息写入 stderr；没有输出目标时退出码 1 属正常探测行为。渲染本身的非零退出码仍应按错误处理。耗时取决于素材、并发、字体、3D 与编码器，以当前项目测量为准。
